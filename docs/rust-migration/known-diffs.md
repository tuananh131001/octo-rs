# Known differences between the C# and Rust builds

Every place the Rust build deliberately behaves differently from C# `2026.10.03.2`, and why.
The parity harness must show no diff that is not listed here.

| Area | C# behaviour | Rust behaviour | Why |
|---|---|---|---|
| Config binding | An empty (`null` from a cleared dashboard field) or unconvertible value for a number, bool or enum setting throws when the section is bound, breaking the whole section until `settings.json` is fixed. | The value is skipped with a warning and the next lower source (env, `appsettings.json`, then the class default) supplies it. | The C# behaviour is a latent bug the dashboard can trigger; see `config.md` §1. |
| Config binding | Enum values combine with commas as a flags OR (`"Track,Album"`). | Not supported; such a value is skipped as unconvertible. | No Octo setting is a flags enum. |
| Packages | Swashbuckle serves `/swagger` in Development. | No Swagger UI. | Never served in any shipped configuration (`packages.md`). |
| Audio tools | `Process.Kill(entireProcessTree: true)` on a timeout or failure. | The ffmpeg/fpcalc process alone is killed (also on drop). | Neither tool starts child processes, so the tree is the process. |
| Spectrum check | Sample rate and duration come from TagLib#. | They come from lofty. | No TagLib in Rust; a file one library reads and the other refuses changes only "the file's format could not be read" (no opinion). |
| Spectrum check | An I/O error reading ffmpeg's pipes escapes `AnalyzeAsync` as an exception, against its own "never throws" contract. | No opinion, "the check failed", with a warning. | `analyze` cannot throw; the documented contract is kept. |
| Fingerprinting | A `"fingerprint"` in fpcalc's JSON that is neither a string nor null throws `InvalidOperationException` out of `FingerprintAsync`. | Treated as output that is not fpcalc's shape: Unavailable (no opinion). | No real fpcalc writes it; an exception into the download loop is what the class exists to prevent. |
| Fingerprinting | A negative `timeoutSeconds` throws `ArgumentOutOfRangeException` after fpcalc has started. | Times out at once: Unavailable. | A setting value cannot be allowed to panic the download loop. |
| Settings path | settings.json is always `/app/config/settings.json`. | Still the default, but the env var `OCTO_SETTINGS_PATH` overrides it (`SettingsStore::default_settings_path`). | Lets the binary run outside the container. Compose never sets it, so the container behaves as before. |
| Settings load | A settings.json that does not parse at startup (`InvalidDataException`) stops the host, which then crash-loops under `restart: unless-stopped`. | An error is logged and the file layer is treated as empty; the server runs on appsettings.json + env, and the watcher picks the file up once it is fixed. | A typo in a hand edit should not take the server down. The writer refuses to overwrite such a file either way. |
| Settings reload | On a reload that does not parse, raw `IConfiguration` reads fall back to "no file" at once while `IOptionsMonitor` caches keep the old values. | The last good snapshot and the last good raw configuration both stay in place, and an error is logged. | config.md §1 recommendation: one consistent view instead of two disagreeing ones. |
| Settings load | `appsettings.json` is read from `/app` and hot-reloads; replacing it (a bind mount) changes the defaults. | It is compiled into the binary (`crates/octo-core/assets/appsettings.json`, plus `appsettings.Development.json`) and never reloads. | It ships inside the image and is not meant to change; compiling it in removes a file the binary depends on. |
| Settings file writer | `Merge` matches patch keys case-sensitively (`JsonObject`), so `subsonic` next to `Subsonic` adds a second key, which the config reader then rejects as a duplicate. | Sections and keys (at every depth, and in `replaceObjects`) match ignoring case; the existing spelling is kept and the value replaced in place. | config.md §4 recommendation: strictly safer, and no well-formed client can tell. |
| Config binding | An enum setting given a number that names no member (`"Subsonic:StorageMode": "7"`) binds to that undefined value, and GET echoes `"7"`. A `HeartDownloadSources` step with such a `Source` is dropped by `EffectiveHeartDownloadSources`. | The value is skipped with a warning like any unconvertible value; a step whose `Source` is skipped keeps the default `Soulseek`. | A Rust enum cannot hold an undefined member. Only a hand-edited file can produce this. |
| Settings load | settings.json with two keys spelled identically (same case) in one object is a `FormatException` (duplicate key). | The later value wins, as `JsonNode` does. Keys differing only in case are still an error. | `json::dom::Node` keeps one value per name; only a hand edit can produce this. |
| List covers: text edges | ImageSharp.Drawing fills the glyph outlines with 8 sub-scanlines of anti-aliasing, one transparent layer per line, laid over the background. | tiny-skia fills the same outlines (skrifa, unhinted) straight onto the background with its own anti-aliasing. Layout is identical: every size, line break, cut, box and baseline of the 66 C# reference layouts (`docs/rust-migration/fixtures/covers/reference.json`) agrees within 0.0002 px, and every one-line advance within 0.0001 px. Pixels on a glyph's edge differ by up to about 100 levels; the 28 reference covers reach SSIM 0.9978 or better against the C# renders (the tests require 0.98, PLAN.md), and the veiled backgrounds match the C# ones exactly (0 levels; tested at 1). | A different rasteriser; the plan accepts anti-aliasing differences. |
| List covers: JPEG bytes | ImageSharp's JPEG encoder: list covers at quality 92, 4:4:4; the badge, placeholder (85, 70), crop-to-square, `ToJpeg` (90) and `FitWithin` (92) at ImageSharp's default chroma subsampling. | The `image` crate's encoder at the same qualities, always 4:4:4 (the only kind it writes). The served "Rock Radio" cover reaches SSIM 0.985 against the C# JPEG. | Bytes were never stable across encoders; covers are cached by the clients per URL, not by hash. |
| List covers: seed colours | A seed cover was decoded with ImageSharp's `TargetSize` 64×64 (scaled JPEG decoding, then a box-filter shrink keeping its shape). | Decoded in full, then shrunk to fit 64×64 with the `image` crate's triangle filter. | The nearest filter the crate has; the swatch buckets are 4 bits a channel, so the music colour moves only for pictures on a bucket edge. |
| List covers: resampling | ImageSharp's bicubic resampler for the logo and covers-folder pictures, Lanczos3 for `FitWithin`. | The `image` crate's Catmull-Rom (the same bicubic) and Lanczos3. | Same kernels, another implementation; a level or two at most. |
| List covers: veil | The yellow-lean sums were added up per row in whatever order the parallel rows finished. | Added in row order. | Deterministic; the sum differs from C#'s in the last bits at most. |
| List covers: Arabic and Hebrew names | Each line was drawn from the top of its box so that a capital H (in Inter, as Noto Arabic and Hebrew have none) sat on the baseline, which sets those names off the baseline the layout computed by the difference between the two fonts' line boxes (an Arabic name in Noto Sans Arabic sits 4.6% of its size higher). | Kept: the port draws them at the same offset. | Parity; noted because it looks like a bug. |
| List covers: seed callbacks | `ListCover.Seeds` and `CoverSeed.Fetch` took a `CancellationToken`, and the 4 s seed budget cancelled it. | The callbacks take nothing; the budget is a `tokio::time::timeout` around them, and dropping `get_list_cover`'s future cancels it. | The Rust idiom for the same behaviour. |
| Background workers | An exception escaping a `BackgroundService.ExecuteAsync` stops the whole host (.NET 8+ `BackgroundServiceExceptionBehavior.StopHost`); Docker's restart policy then restarts the container. Every Octo worker catches per item or tick to avoid this. | `WorkerSupervisor` logs the failure (error or panic) and restarts that worker alone after a backoff (1 s doubling to 60 s, reset after a 60 s healthy run); the server keeps running. A worker that returns `Ok(())` has finished and is not restarted, as before. | A bug in one worker should not take the proxy down; Octo's own code treated StopHost as a disaster to avoid. |
| Static files | `Accept-Ranges: bytes` is sent twice (`MapStaticAssets` and the range processing each add it). | Sent once. | The duplicate is an ASP.NET quirk; one header means the same to every client. |
| Static files | Brotli/gzip variants come from the build's compressor; their bytes, `Content-Length` and first `ETag` differ from Rust's, and their `Last-Modified` is the compression time. `Last-Modified` of the plain file is the build time. | Variants are compressed at startup (Brotli quality 11, gzip best); `Last-Modified` is the source file's modification time for every variant. The plain file's ETag (base64 SHA-256) is identical. | Different compressors cannot produce the same bytes; the second (`W/`) ETag still names the original. |
| Static files | Every file in `wwwroot` is served (any name, any type the build manifest recorded). | Files with an unknown extension, or a name that would need URL encoding, are skipped (logged at debug). | Only `.html/.css/.js/.svg/.png` ship today; this keeps the route table to plain literals. |
| HTTP | Every response carries `Server: Kestrel`. Bodies written with `WriteAsJsonAsync`/`JsonResult` go out chunked. | No `Server` header. Full bodies carry `Content-Length`. Header names are lower-case (HTTP/1.1 via hyper). | Claiming to be Kestrel would be false; length vs chunked framing is invisible to clients. The parity differ must ignore `Server`, `Transfer-Encoding`/`Content-Length` framing and header-name case. |
| Logging | Levels come from the merged configuration (`Logging:LogLevel:*` in env, appsettings or settings.json) and hot-reload. Output is the .NET console formatter (`info: Category[id]` + message). | Levels come from `RUST_LOG`, else the `Logging__LogLevel__*` environment variables (categories mapped to Rust targets: `Octo.X.Y` → `octo::x::y`, `Microsoft.AspNetCore` → the request lines plus axum/hyper, `System.Net.Http` → reqwest), read once at startup. Output is `tracing`'s formatter. The redaction and the request-line wording are kept. | A `Logging` section in settings.json is not a supported setting (the dashboard never writes one); log text is not a parity surface. |
| Logging | `Logging:LogLevel` names are matched case-insensitively against categories. | Rust targets match case-sensitively; the known .NET categories are mapped to the spelling the port logs under. | `tracing`'s filter is case-sensitive. |
| Unicode data | `char.IsLetter`, casing, NFKC and the regex classes use .NET 9's tables (Unicode 15.1) and the host's ICU. | `octo_core::common::dotnet` reproduces .NET's rules (UTF-16 units, simple casing with the İ/ı/ſ exceptions, .NET's `\b` word set), but over Rust's own Unicode tables (16/17). | Only characters assigned after Unicode 15.1 can classify or case differently. Everything else was compared against .NET 9 code point by code point. |
| Regex case-insensitivity | Patterns built with `IgnoreCase` but not `CultureInvariant` follow the process culture: under en-US, `(?i)i` also matches `İ` (U+0130), so for example `[İ]` reads as a part number. | Always the invariant culture's equivalences (`i`↔`I`, `k`↔`K`↔`K`, `s`↔`S` only). | The container sets no `LANG`, so production C# ran with the invariant culture; this keeps that behaviour wherever Octo runs. |
| `downloads-history.json` | A JSON `null` in a non-nullable C# `string`/list property (`Artist`, `Title`, `Path`, `Format`, `Source`, `DownloadedAt`, and the `TagReport` strings and lists) is read as null and written back as `null`. | Read as the empty value and written back as `""` / `[]` / `{}`. | Only a hand-edited file has such a null; reading it at all (rather than failing the whole log) is what matters. |
| Relay errors (3-E) | The "Error connecting to Subsonic server: ..." / "Error streaming from Subsonic: ..." text ends with the .NET exception's `Message`. | The not-configured, scheme, relative-URI, refused-connection (`Connection refused (host:port)`), DNS (resolver's own words + `(host:port)`), timeout and non-success-status texts are reproduced; any other transport failure carries reqwest's description. | .NET's messages for every socket/TLS failure cannot be reproduced generally. |
| Faithful relay headers (3-E) | `HttpResponseMessage` re-wrote headers as it parsed them; `Cache-Control` with a directive .NET does not model in the same way could be re-ordered or normalised further than the port does. | Lists (`Vary`, `Accept-Ranges`) split with the last value kept, `Cache-Control` merged into .NET's directive order, `Last-Modified` re-written as RFC 1123, `Content-Type` re-spaced as `MediaTypeHeaderValue` did; other values pass as received. | The common Navidrome headers come out byte-identical (checked against .NET 9); exotic Cache-Control extensions may still differ. |
| Request parsing (3-E) | A url-encoded form over `FormOptions` limits failed part way and the fallback parsed what remained of the body; a form's `charset` other than UTF-8 was honoured; a JSON string with a lone surrogate escape threw (500). | Over the limits the form contributes nothing; bodies are read as UTF-8; such a JSON body is ignored. | Only a malicious or broken client sends any of these. |
| Upstream requests (3-E) | HttpClient sent no `Accept` header of its own. | reqwest adds `Accept: */*` when the client sent none (the faithful relay forwards the client's own). | reqwest default; Navidrome ignores it. |
| Credential/identity checks (3-E) | `CheckAsync`/`UsernameAsync` take a `CancellationToken`; a cancelled caller gets Unreachable/null. A `tokenInfo` `status` that is not a string threw `InvalidOperationException`. | A caller that gives up drops the future; the shared call carries on. A non-string status reads as "not named". | Rust cancellation is by dropping; the second is an exception nothing could act on. |
| `rejected-peers.json` | The recency list removed keys case-sensitively, so one peer file denied twice with different casing (`Peer1` then `peer1`) stayed in the list twice and was written to the file twice. | One entry, keyed by the case-folded key throughout. | The duplicate line is an accident of `LinkedList.Remove`; both builds read either file back to the same single denial. |
| `external-ids.json`, `rejected-peers.json` | An id (or peer file) listed twice in the file was kept at both places in the recency list and written twice by the next flush. | Kept once, at its most recent place, with the later entry's value. | Only a hand edit produces such a file. |
| State-file enums | An enum number no member names (`"Kind":7` in `external-ids.json` or `soulseek-holds.json`, `"ShownDurationSource":9`) is read and written back as that number. | The file fails to load and the store starts empty (with the usual warning). | A Rust enum cannot hold an undefined member; only a hand edit produces one. |
| State-file flushes | The timer flush and an explicit one (`RejectedPeerRegistry.Clear`, `Dispose`) could run at once and race on `<file>.tmp`. | Flushes of one store take a lock. | Removes a race; the bytes written are the same. |
| Release notes | Notes longer than 20,000 UTF-16 units were cut at exactly 20,000, which could leave half of a surrogate pair (written as a lone `\uD83D`). | The cut drops a pair it would split, so the notes can be one unit shorter. | A lone surrogate is not valid UTF-8; Rust strings cannot hold one. |
| Folder picker | On Windows an empty path listed the drives. | Always the Unix root. | Octo runs in a Linux container only. |
| Release details and database candidates | A block of the wrong JSON kind where an object is expected (an artist credit, track or medium that is a string or number, a non-string in `secondary-types`) makes `TryGetProperty`/`GetString` throw out of `ReleaseDetails.Parse`, `CandidateSources.FromDatabaseSearch` and `FromIsrcLookup`; the caller loses the whole answer. | That block reads as absent and the rest of the answer is kept. | MusicBrainz never sends such a shape; `serde_json::Value` has no throwing accessors to mirror. |
| File names | `SanitizeFileName`/`SanitizeFolderName` cut a long name at 100 UTF-16 units, which can split a surrogate pair and leave a lone surrogate in the path. | The character the cut would split is left out whole (the name is 99 units). | A Rust string cannot hold a lone surrogate; only names of exactly that shape differ. |
| Tagging sources | `ReleaseIdentifier` and `TagPreview` passed linked `CancellationToken`s with `CancelAfter(budget)` into `MusicBrainzClient`, `DeezerMetadataService` and the loudness meter. | The calls go through traits without a token; a budget is `tokio::time::timeout` and the caller's token a `select!`, and the call's future is dropped. The prefetch is a spawned task left to finish when unused, as the C# task was. | The Rust idiom for the same behaviour; every note and stage time is kept. |
| Lyrics time tags, release versions | The LRC tag patterns (`[mm:ss.xx]`, `<mm:ss.xx>`) and `ReleaseVersion`'s pattern used `\d`, which in .NET also matches other scripts' decimal digits (`[٠١:٠٢]`, `٢٠٢٦.١٠.٠٢`); `long.Parse`/`int.Parse` then threw `FormatException` out of `ParseLrc`, `StripCredits`, `ReleaseVersion.TryParse` and `UpdateHost.Request`, while `HasTimestamps`/`HasWordTags` said yes. | Only ASCII digits make a tag or a release; such text is plain lyrics, and such a tag is not a release. | An exception from a parser that has a "no" answer; no real lyric or tag is written that way. |
| `update/status`, `update/helper` times | `DateTime.TryParse` with the invariant culture also read culture formats (`10/03/2026`, `Oct 3 2026 18:05`). | ISO 8601 only (`T` or space, optional fraction and offset, or a date alone). | The helper writes `date -u +%Y-%m-%dT%H:%M:%SZ`; nothing else writes these files. |
| `update/log` | An unreadable log (permission denied) threw `UnauthorizedAccessException` out of `UpdateHost.LogTail`, failing the update card. | An empty tail, as for a missing log or an I/O error. | `LogTail` caught `IOException` for exactly this; the permission case was an oversight. |
| `genre-backfill.json`, `genre-backfill-journal.jsonl`, `lyrics-choices.json` | A JSON `null` in a non-nullable C# string or list (`RunId`, `Errors`, `Queue`, `Preview`, a change's `Path`/`Action`/`Before`/`After`, a journal line's `b`/`a`/`r`, a pin's `Choice`, a result's `Source`) is read as null and written back as `null`. An enum number that names no member (`"Status":9`) is read and written back. | Read as the empty value and written back as `""` / `[]`. An undefined enum number fails the read: the run starts Idle with a warning, as for any unreadable state. | Only a hand-edited file has these; the same reading as `downloads-history.json`. |
| Metadata clients: cancellation | `DeezerMetadataService`, `MusicBrainzClient`, the cover sources and the iTunes lookup take a `CancellationToken`; where C# let the `OperationCanceledException` escape (a shared Deezer search, MusicBrainz's gate, the iTunes gate), the caller saw it thrown. | No token: a caller cancels by dropping the future, and sees nothing. Shared fetches (Deezer's artist search, track count and album year) run on their own task and still finish and fill the cache, as the C# fetches ran on without their awaiters. | The Rust idiom for the same behaviour; no caller can tell an exception it asked for from a future it dropped. |
| AcoustID background lane | `AcoustIdRateLimiter.InBackgroundAsync` set an `AsyncLocal`, which also flowed into tasks started inside the work. | A tokio `task_local`, which does not reach a task the work spawns. | The sweep's lookups are awaited inline, so nothing relied on the flow. |
| Metadata caches | `MemoryCache` with a `SizeLimit` compacts on a background thread when an entry does not fit, and drops expired entries on a one-minute scan. | `services::framework::MemoryCache` compacts in place, at once (expired first, then least recently read, down to 95%), and drops an expired entry when it is read. | Same bound, same eviction order; only the timing of the clean-up differs. |
| `itunes-masters.json` row order | Rows are written in `ConcurrentDictionary` enumeration order (unspecified). | Insertion order (an `IndexMap`), so a file loaded and written back keeps its order. | Any order was valid; this one makes the round trip byte for byte. |
| iTunes master probe | `HttpCompletionOption.ResponseHeadersRead`: the client's 20 s timeout covered the headers of the ranged request, not reading its first 64 KB. | reqwest's timeout covers the whole request, reading included. | Reading 64 KB inside 20 s is never the slow part. |
| iTunes release suffix | `\s+-\s+(?:Single|EP)\s*$` with `IgnoreCase | CultureInvariant`: `ſ` (U+017F) and the Kelvin sign are not `s`/`k`. | Rust `(?i)` simple case folding also matches `ſingle` and `EP` written with look-alikes. | A collection name spelled with a long s does not occur in Apple's catalog. |
| Accept-Language (stub) | `AcceptLanguageHeader.Apply` drops any comma-separated part the header parser rejects, and the collection writes `en; q=0.9` for `en;q=0.9`. | Until 2-B lands, the trimmed parts are sent as written, joined with `, `. | STUB(2-B): `octo_core::metadata::accept_language_header` is replaced by the real port. |
| Lyrics sources: an answer of an unexpected shape | `JsonElement` threw when a source read a property off something that is not an object (a JSON array where LRCLIB's entry belongs, KuGou's `"data"` not an object, NetEase's `"lrc": null`), called `GetString` on a non-string, or `GetInt64` on a fraction; and KuGou's `long.Parse` threw on a KRC time too big for a `long`. LRCLIB and KuGou let it out of `FindAsync` (the service caught it: a failed lookup), `SearchAsync` (`LyricsChoiceService` caught it: no entries from that source) and `FetchAsync` (in `LyricsChoiceService.CandidatesAsync`: no further entries from that source; in `LyricsOfAsync`: an exception to the controller). NetEase and lyrics.ovh caught it themselves as a failed lookup. | The source returns a failed (transient) lookup or search in every case, and `lyrics_of` returns None. A KRC line whose times do not fit is skipped. | The outcome on the main path (`LyricsService.Find`) is the same; the others only differ for answers no service sends. |
| Lyrics: cancellation | LRCLIB's `SearchAsync`/`FetchAsync`, all of KuGou, and `LyricsChoiceService.LyricsOfAsync` let `OperationCanceledException` out when the caller's budget ran out. | They return a failed lookup or search (`lyrics_of`: None); every caller checks the token as the C# callers did. | No exceptions in the trait. 6-A must answer a None from `lyrics_of` with the token cancelled the way the controller answered the exception. |
| `lyrics-undo.jsonl` | A JSON `null` (or nothing) for an entry's `Path`, `Kind` or `RunId` was read as null, and a missing `AtUtc` as `DateTime.MinValue`. | Read as `""` and `DateTime.MinValue`; the entry is kept, as in C#. The file is never rewritten, so nothing is written back. | The same reading as the other journals. |
| Last.fm, ListenBrainz: timeouts and cancellation (3-B) | An `HttpClient` timeout is a `TaskCanceledException`, an `OperationCanceledException`, which `LastFmService` (100 s client) and `ListenBrainzService` (10 s) let out of their methods (`catch ... when (ex is not OperationCanceledException)`): the caller saw it thrown. The radio methods, `SearchTracksAsync`, `GetArtistTopTracksAsync`, the scrobbler's Connect/Check calls and `ValidateTokenAsync` took a `CancellationToken`. | A client timeout is an ordinary failure: logged, and the method answers as for any failure (an empty list, `false`, or a refusal whose detail is .NET's timeout text). No token: a caller cancels by dropping the future. | The same rule as the 2-D metadata clients. The scrobbler already treated a timeout as "unreachable", and every C# caller of these methods caught and logged what escaped. |
| Last.fm readers: element shapes (3-B) | `LastFmService`'s radio methods (`GetSimilarArtistsAsync`, the two tag methods, `GetTagTopTracksAsync`, `GetTrackInfoAsync`) threw out of the method when an element of Last.fm's answer was not the kind read (`TryGetProperty` on a string, say). | They return `Err(ElementError)` at the same places; the callers (5-C) decide, as the C# callers' catches did. The other readers answer empty and log, as their C# catch did. | `Result` is how a Rust caller sees what C# threw. |
| Last.fm scrobbler: odd answers (3-B) | `GetValue<string>()` on a non-string `token`, `session.key`, `session.name`, `message` or a stored `SessionKey` threw `InvalidOperationException`: out of Begin/Finish (a 500 from the admin API), out of `CallAsync`, or inside `RemoveSavedSession`'s `Update` (caught: nothing written). | A non-string is read as absent ("Last.fm sent no token.", "Last.fm sent no session key.", an empty message, a key that does not match). A `scrobbles`/`@attr` that is not an object still counts as the unexpected failure the drain catches. | Last.fm only ever sends strings there; a 500 helps nobody. |
| Discord embed limits (3-B) | `Truncate` cut at a UTF-16 index, so a cut through a surrogate pair kept its first half, which the default encoder then wrote as a lone `\uD83C`. | The pair is left out whole. | A Rust `String` cannot hold half a pair; Discord would show a replacement character either way. |
| Error texts surfaced verbatim (3-B) | The scrobbler's "Last.fm could not be reached: …", `ValidateTokenAsync`'s detail and the notification test results end with the .NET exception's `Message`. | Refused connections, DNS failures, timeouts (`http_client_factory`), non-success statuses (`Response status code does not indicate success: 404 (Not Found).`), ntfy's `UriFormatException` texts and `ElementError`'s texts are reproduced; other transport and JSON-syntax failures carry reqwest's or serde_json's description. | .NET's messages for every socket, TLS and parser failure cannot be reproduced generally. |
| Subsonic answers: Navidrome JSON read for a merge | `ConvertJsonValue` kept a literal `-0` as the `int` 0 (written `0`), and threw on a duplicate key inside a nested object, failing the whole search read. The extensions merge and the sync catalog page used `JsonNode.Parse`, which refuses comments and trailing commas (the extensions answer is then passed through untouched; the sync page throws). | `-0` is read as the double -0 (written `-0`); a nested duplicate key keeps its last value. The extensions merge and the sync page read through `json::dom::Node`, which accepts comments and trailing commas (and drops them on the write). | serde_json does not keep a number's text, and the DOM that keeps numbers verbatim is the lenient one; Navidrome writes none of these. |
| Subsonic answers: Navidrome XML read for a merge | `XDocument.Parse` kept a DOCTYPE and processing instructions and wrote them back; a prefixed element or attribute name was resolved to its namespace. | Not kept; a prefixed name is kept as written and its prefix not resolved (`xmlns` declarations, comments and CDATA are kept as .NET kept them). | Navidrome writes plain, unprefixed XML in one default namespace. |
| Subsonic answers: impossible inputs | An external playlist with an empty provider threw (`Provider[0]`); a song with a null title fell back to "Singles" as its album; the summed durations of a playlist or album threw `OverflowException` past 2^31 seconds; a JSON library row reaching the XML search merge threw `InvalidCastException`. | An empty provider gives the artist `🎵 `; a title is never null in Rust; durations are summed as 64-bit; a JSON row is skipped by the XML merge. | None of these can happen: providers are fixed names, models carry non-null strings, and rows are read as JSON exactly when the merge is JSON. |
| slskd login state (4-A) | `connectionWatchdog.nextAttemptAt` is read with `DateTime.TryParse` (invariant culture), which also takes forms such as `10/03/2026 05:48:13`. | Only ISO 8601 is read (`json::datetime::parse_utc`); anything else is no next try. | slskd writes ISO 8601; the value only feeds the dashboard's "tries again at" words. |
| Transfer wait (4-A) | An exception thrown by the `onProgress` listener is caught and logged at debug. | The listener is a plain `Fn` that has no error to return. | Nothing can be caught; the listeners Octo passes only record numbers. |
| Song lengths (stub, 4-A) | When Deezer has no length, `LastFmService.GetTrackInfoAsync` is asked before a video's length. | Until 3-B lands, `AppState` gives `SoulseekMetadataService` no Last.fm source, so the chain goes from Deezer to the video. | STUB(3-B): `LastFmService` implements `soulseek_metadata_service::LastFmTrackLengths` and is passed in `app.rs`'s `SoulseekServices::build`. |
| Song lengths | A Last.fm `track.getInfo` answer the reader refuses made `CompleteLengthAsync` throw, skipping its last step (the yt-dlp probe). | That answer counts as no length and the yt-dlp probe is still tried. | The trait seam returns an `Option`; the probe is the more useful outcome. |
