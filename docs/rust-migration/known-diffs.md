# Known differences between the C# and Rust builds

Every place the Rust build deliberately behaves differently from C# `2026.10.03.2`, and why.
The parity harness must show no diff that is not listed here.

| Area | C# behaviour | Rust behaviour | Why |
|---|---|---|---|
| Config binding | An empty (`null` from a cleared dashboard field) or unconvertible value for a number, bool or enum setting throws when the section is bound, breaking the whole section until `settings.json` is fixed. | The value is skipped with a warning and the next lower source (env, `appsettings.json`, then the class default) supplies it. | The C# behaviour is a latent bug the dashboard can trigger; see `config.md` §1. |
| Config binding | Enum values combine with commas as a flags OR (`"Track,Album"`). | Not supported; such a value is skipped as unconvertible. | No Octo setting is a flags enum. |
| Packages | Swashbuckle serves `/swagger` in Development. | No Swagger UI. | Never served in any shipped configuration (`packages.md`). |
| Audio tools | `Process.Kill(entireProcessTree: true)` on a timeout or failure. | The ffmpeg/fpcalc process alone is killed (also on drop). | Neither tool starts child processes, so the tree is the process. |
| Spectrum check | Sample rate and duration come from TagLib#. | They come from lofty. | No TagLib in Rust; a file one library reads and the other refuses changes only "the file's format could not be read" (no opinion). |
| Spectrum check | An I/O error reading ffmpeg's pipes escapes `AnalyzeAsync` as an exception, against its own "never throws" contract. | No opinion, "the check failed", with a warning. | `analyze` cannot throw; the documented contract is kept. |
| Fingerprinting | A `"fingerprint"` in fpcalc's JSON that is neither a string nor null throws `InvalidOperationException` out of `FingerprintAsync`. | Treated as output that is not fpcalc's shape: Unavailable (no opinion). | No real fpcalc writes it; an exception into the download loop is what the class exists to prevent. |
| Fingerprinting | A negative `timeoutSeconds` throws `ArgumentOutOfRangeException` after fpcalc has started. | Times out at once: Unavailable. | A setting value cannot be allowed to panic the download loop. |
| Settings path | settings.json is always `/app/config/settings.json`. | Still the default, but the env var `OCTO_SETTINGS_PATH` overrides it (`SettingsStore::default_settings_path`). | Lets the binary run outside the container. Compose never sets it, so the container behaves as before. |
| Settings load | A settings.json that does not parse at startup (`InvalidDataException`) stops the host, which then crash-loops under `restart: unless-stopped`. | An error is logged and the file layer is treated as empty; the server runs on appsettings.json + env, and the watcher picks the file up once it is fixed. | A typo in a hand edit should not take the server down. The writer refuses to overwrite such a file either way. |
| Settings reload | On a reload that does not parse, raw `IConfiguration` reads fall back to "no file" at once while `IOptionsMonitor` caches keep the old values. | The last good snapshot and the last good raw configuration both stay in place, and an error is logged. | config.md §1 recommendation: one consistent view instead of two disagreeing ones. |
| Settings load | `appsettings.json` is read from `/app` and hot-reloads; replacing it (a bind mount) changes the defaults. | It is compiled into the binary (`crates/octo-core/assets/appsettings.json`, plus `appsettings.Development.json`) and never reloads. | It ships inside the image and is not meant to change; compiling it in removes a file the binary depends on. |
| Settings file writer | `Merge` matches patch keys case-sensitively (`JsonObject`), so `subsonic` next to `Subsonic` adds a second key, which the config reader then rejects as a duplicate. | Sections and keys (at every depth, and in `replaceObjects`) match ignoring case; the existing spelling is kept and the value replaced in place. | config.md §4 recommendation: strictly safer, and no well-formed client can tell. |
| Config binding | An enum setting given a number that names no member (`"Subsonic:StorageMode": "7"`) binds to that undefined value, and GET echoes `"7"`. A `HeartDownloadSources` step with such a `Source` is dropped by `EffectiveHeartDownloadSources`. | The value is skipped with a warning like any unconvertible value; a step whose `Source` is skipped keeps the default `Soulseek`. | A Rust enum cannot hold an undefined member. Only a hand-edited file can produce this. |
| Settings load | settings.json with two keys spelled identically (same case) in one object is a `FormatException` (duplicate key). | The later value wins, as `JsonNode` does. Keys differing only in case are still an error. | `json::dom::Node` keeps one value per name; only a hand edit can produce this. |
| Background workers | An exception escaping a `BackgroundService.ExecuteAsync` stops the whole host (.NET 8+ `BackgroundServiceExceptionBehavior.StopHost`); Docker's restart policy then restarts the container. Every Octo worker catches per item or tick to avoid this. | `WorkerSupervisor` logs the failure (error or panic) and restarts that worker alone after a backoff (1 s doubling to 60 s, reset after a 60 s healthy run); the server keeps running. A worker that returns `Ok(())` has finished and is not restarted, as before. | A bug in one worker should not take the proxy down; Octo's own code treated StopHost as a disaster to avoid. |
| Static files | `Accept-Ranges: bytes` is sent twice (`MapStaticAssets` and the range processing each add it). | Sent once. | The duplicate is an ASP.NET quirk; one header means the same to every client. |
| Static files | Brotli/gzip variants come from the build's compressor; their bytes, `Content-Length` and first `ETag` differ from Rust's, and their `Last-Modified` is the compression time. `Last-Modified` of the plain file is the build time. | Variants are compressed at startup (Brotli quality 11, gzip best); `Last-Modified` is the source file's modification time for every variant. The plain file's ETag (base64 SHA-256) is identical. | Different compressors cannot produce the same bytes; the second (`W/`) ETag still names the original. |
| Static files | Every file in `wwwroot` is served (any name, any type the build manifest recorded). | Files with an unknown extension, or a name that would need URL encoding, are skipped (logged at debug). | Only `.html/.css/.js/.svg/.png` ship today; this keeps the route table to plain literals. |
| HTTP | Every response carries `Server: Kestrel`. Bodies written with `WriteAsJsonAsync`/`JsonResult` go out chunked. | No `Server` header. Full bodies carry `Content-Length`. Header names are lower-case (HTTP/1.1 via hyper). | Claiming to be Kestrel would be false; length vs chunked framing is invisible to clients. The parity differ must ignore `Server`, `Transfer-Encoding`/`Content-Length` framing and header-name case. |
| Logging | Levels come from the merged configuration (`Logging:LogLevel:*` in env, appsettings or settings.json) and hot-reload. Output is the .NET console formatter (`info: Category[id]` + message). | Levels come from `RUST_LOG`, else the `Logging__LogLevel__*` environment variables (categories mapped to Rust targets: `Octo.X.Y` → `octo::x::y`, `Microsoft.AspNetCore` → the request lines plus axum/hyper, `System.Net.Http` → reqwest), read once at startup. Output is `tracing`'s formatter. The redaction and the request-line wording are kept. | A `Logging` section in settings.json is not a supported setting (the dashboard never writes one); log text is not a parity surface. |
| Logging | `Logging:LogLevel` names are matched case-insensitively against categories. | Rust targets match case-sensitively; the known .NET categories are mapped to the spelling the port logs under. | `tracing`'s filter is case-sensitive. |
